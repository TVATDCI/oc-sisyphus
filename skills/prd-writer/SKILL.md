# PRD Writer

Transforms an approved brief into a structured PRD (Product Requirements Document). Runs mandatory momus-prd-reviewer gate before completion.

## Entry Criteria

- [ ] Brief validated by `brief-loader` (complete, in context)
- [ ] Reference check passed (no naming conflicts via `reference-checker`)
- [ ] Project root resolved

## Produces

- PRD file at `.sisyphus/prds/{name}-prd.md`
- User story count, vertical slice count
- Momus PRD review report (gate result)

## Next if Approved

- **PASS**: Delegate to `momus-prd-reviewer` for deep review (mandatory gate)
- **WARNING**: Delegate to `momus-prd-reviewer` with caution notes

## Next if Rejected

- **Reference-check FAIL**: STOP. Resolve naming conflicts, retry (max 3)
- **Momus FAIL**: Return to Step 1-4 for fixes, retry review (max 3)
- **Momus FAIL (3x)**: Escalate to user for manual review

## Model Selection

**Category:** `deep` → `gpt-5.4`

**Rationale:** PRD writing requires reasoning, asking questions, finding blockers. This is judgment work, not mechanical execution.

**Model Transparency:**
When delegating to subagents, always report: `Executing with [model] via [category]` (e.g., "Executing with gpt-5.4 via deep").

## Input

- Validated brief (from brief-loader output or session context)
- Optional: existing PRD template preference

## Steps

0. **Checkpoint 2: Reference Verification**
   Before drafting, verify no naming conflicts:
   ```
   Delegate to reference-checker:
     artifact_name = {PRD slug}
     artifact_type = "prd"
     project_root = {resolved}
   ```
   
   | Decision | Action |
   |----------|--------|
   | PASS | Proceed with PRD drafting |
   | WARNING | Proceed with caution. Log related work |
   | FAIL | STOP. "Cannot draft PRD — conflicts found." Resolve and retry (max 3) |

1. **Summarize design concept** from brief
   - Problem statement: what pain point or opportunity?
   - Solution overview: what does end state look like?
   - Out-of-scope items: what is NOT included

2. **Draft user stories**
   - Format: "As a [role], I want [feature], so that [benefit]"
   - Each story must be testable
   - Group by vertical slice, not by system layer

3. **Record implementation decisions**
   - Deep module boundaries: small interface + large hidden implementation
   - Decision Log: each major choice with rejected alternative and rationale
   - Technology choices with rationale
   - Integration points with existing systems

4. **Record testing decisions**
   - Feedback loops: tests, types, linting
   - TDD approach: red → green → refactor
   - Manual QA checkpoints: human-in-the-loop verification

5. **Check for DESIGN.md (if UI is in scope)**
    ```bash
    [ -f {project_root}/DESIGN.md ] && echo "DESIGN.md found" || echo "No DESIGN.md"
    ```
    - If found: read and reference design constraints in PRD
    - If not found and UI is in scope: note in PRD that visual design is unconstrained — recommend creating DESIGN.md

6. **Consume DESIGN.md v1.1.0 sections (if UI is in scope)**
    
    > Only applies when DESIGN.md exists and was generated by `website-analyzer` ≥ v1.1.0 with Sections 10–14.

    Parse each section and translate findings into PRD hardening constraints:

    | Section | Parsed Content | Hardening Mapping |
    |---------|---------------|-------------------|
    | **10. CSS Architecture** | Specificity, `!important`, CSS Layers, z-index, animation patterns | Checklist items for specificity caps, layer order enforcement, z-index token scale, GPU-only animations |
    | **11. Accessibility** | Focus indicators, ARIA, reduced-motion, contrast | Checklist items for `:focus-visible`, `prefers-reduced-motion`, WCAG AA contrast, landmark elements |
    | **12. Browser Support** | Modern CSS features, fallback strategies, support matrix | Checklist items for `@supports` fallbacks, polyfill decisions, baseline browser contracts |
    | **13. Performance Budget** | CSS size, animation count, font loading | Checklist items for animation budget limits, critical CSS threshold, `font-display` strategy |
    | **14. Risk Assessment** | High / Medium / Low risk items | **HIGH** risks become PRD requirements (not optional); **MEDIUM** risks become warnings; **LOW** risks noted for awareness |

    **Auto-population rules:**
    - For every HIGH risk in Section 14, add a corresponding hardening checklist item and make it a PRD requirement
    - For every `!important` found in Section 10, add "Audit `!important` usage — must be limited to `@layer overrides`"
    - For missing `:focus-visible` in Section 11, add "Implement `:focus-visible` with `--focus-ring` token on all interactive elements"
    - For CSS Color Module L5 in Section 12 without fallback, add "Firefox `@supports not` fallback required for both themes"
    - For unthrottled handlers in Section 10, add "Throttle scroll/resize with `requestAnimationFrame`"
    - For layout-property animations in Section 10, add "Animate only `transform` and `opacity` for GPU compositing"
    - If z-index is ad-hoc in Section 10, add "Replace ad-hoc z-index with systematic token scale"
    - If `prefers-reduced-motion` is ignored in Section 11, add "Respect `prefers-reduced-motion` — disable non-essential animations"
    - If hardcoded colors found in Section 10, add "Zero hardcoded colors — use design tokens exclusively"
    - If Section 13 animation count exceeds 3 simultaneous, add "Cap simultaneous animations to budget limit"

7. **Write PRD to `.sisyphus/prds/`**
    ```bash
    PRD_NAME="{slug}"
    PRD_FILE=".sisyphus/prds/${PRD_NAME}-prd.md"
    mkdir -p {project_root}/.sisyphus/prds
    ```
    - Use template from `.sisyphus/templates/prd-template.md` if exists in project
    - Otherwise use bundled template from skill directory: `~/.config/opencode/skills/prd-writer/prd-template.md`
    - Otherwise create with required sections inline (see PRD Structure below)
    - **Include auto-populated hardening checklist** from Step 6 in the PRD

8. **Checkpoint 1: PRD Deep Review (mandatory)**
    ```
    Delegate to momus-prd-reviewer:
      Input: PRD path = .sisyphus/prds/{name}-prd.md
      Purpose: Find contradictions, scope creep, untestable criteria, risks
    ```
    
    | Decision | Action |
    |----------|--------|
    | PASS | Proceed to present PRD to user |
    | WARNING | Proceed. Log warnings. Mention at next human-in-loop point |
    | FAIL | STOP. "PRD has blockers. Fixing required." Return to Steps 1-4. Retry (max 3) |

9. **Present PRD to user**
    Report:
    - PRD file path
    - User story count
    - Vertical slice count
    - Momus review result (PASS/WARNING/FAIL)
    - DESIGN.md v1.1.0 sections consumed (yes/no — if yes, list hardening items auto-populated)
    - Ask: "PRD ready. Approve to create issues?"

## PRD Structure (Required)

- Problem Statement
- Solution Overview
- User Stories (testable, grouped by vertical slice)
- **Design Requirements** (if UI is in scope)
  - Reference to `DESIGN.md` if it exists
  - Visual constraints: color tokens, typography, spacing rules
  - Component states and responsive behavior
  - Anti-patterns to avoid (from DESIGN.md or project-specific)
- **Hardening Checklist** (auto-populated from DESIGN.md v1.1.0 Sections 10–14 when available)
  - CSS Architecture items (specificity, !important, layers, z-index, animation rules)
  - Accessibility items (focus, motion, contrast, ARIA)
  - Browser support items (fallback strategies, polyfills)
  - Performance budget items (animation limits, CSS size, font loading)
  - Risk assessment items (HIGH risks as requirements, MEDIUM as warnings)
- Implementation Decisions
  - Module Boundaries table: Module | Interface (small) | Hides (large)
- Decision Log: choice + rejected alternative + rationale
- Testing Decisions (feedback loops, TDD, manual QA)
- Out of Scope
- Open Questions / Risks

## PRD Hardening Checklist

Verify before Momus review:

### Generic (always apply)
- [ ] Content Boundaries defined (truncation, max sizes)
- [ ] Score/Metric Normalization (ranges, meanings)
- [ ] Fixture/Test Data Provenance
- [ ] Latency/Performance Contracts
- [ ] Token/Rate Limits with fallback behavior
- [ ] Error Boundaries (explicit, not "handle gracefully")
- [ ] State/Persistence Contract (where, lifecycle, cleanup)
- [ ] **Shared packages first:** If architecture specifies shared packages (e.g., `@project/api-client`, `@project/shared-types`), they must be created in Milestone 1 before any app code. Do NOT defer to later milestones.
- [ ] **No inline API calls:** All data fetching must be extracted to shared hooks in `hooks/` or services in `services/`. Do NOT allow inline `fetch` calls in components.
- [ ] **Mid-build architecture checkpoint:** After ~30% of milestones, pause and verify the architecture is holding. Add an explicit checkpoint slice that verifies modularity before continuing.
- [ ] **MVP-first scope:** Define the smallest useful version first, then expansions. If the feature list is too big, explicitly recommend what to cut.

### From DESIGN.md Section 10 — CSS Architecture (auto-populated)
- [ ] **Specificity Cap:** No selector exceeds agreed max specificity (e.g., 0,3,0). No `!important` outside `@layer overrides`.
- [ ] **CSS Layers Enforced:** If `@layer` is used, ALL styles reside in layers; no unlayered overrides bypass the cascade.
- [ ] **Z-Index Token Scale:** Replace ad-hoc z-index values with systematic token scale (e.g., `--z-base`, `--z-sticky`, `--z-modal`).
- [ ] **GPU-Only Animations:** Animate ONLY `transform` and `opacity`. No layout-property animations (`top`, `left`, `width`, `height`, `margin`, `padding`).
- [ ] **Throttled Handlers:** All `scroll` and `resize` listeners use `requestAnimationFrame` throttling; no unthrottled handlers.
- [ ] **Token Compliance:** Zero hardcoded color values outside `tokens.css` / design-token files.

### From DESIGN.md Section 11 — Accessibility (auto-populated)
- [ ] **Focus-Visible Everywhere:** All interactive elements have `:focus-visible` styles using `--focus-ring` token.
- [ ] **Reduced Motion Respected:** `@media (prefers-reduced-motion: reduce)` disables non-essential animations; essential animations are documented.
- [ ] **WCAG AA Contrast:** All body text meets 4.5:1 minimum; large text meets 3:1. Focus indicators visible against backgrounds.
- [ ] **Semantic Landmarks:** Page uses `<header>`, `<nav>`, `<main>`, `<footer>`, `<article>`, `<section>` correctly.
- [ ] **Heading Hierarchy:** Single `<h1>` per page, no skipped levels (`h1` → `h2` → `h3`).
- [ ] **ARIA Labels:** All interactive elements without visible text have `aria-label` or `aria-labelledby`.

### From DESIGN.md Section 12 — Browser Support (auto-populated)
- [ ] **Modern CSS Fallbacks:** Every modern feature (CSS Color Module L5, `@layer`, `:has()`, `dvh`/`lvh`) has `@supports not` or polyfill fallback.
- [ ] **Baseline Browser Contract:** Support matrix documented; graceful-degradation features identified for ESR / -2 versions.

### From DESIGN.md Section 13 — Performance Budget (auto-populated)
- [ ] **Animation Budget:** Simultaneous animations capped to limit (default ≤ 3). Scroll-linked animations reviewed for performance risk.
- [ ] **Critical CSS Threshold:** Above-the-fold CSS size documented; unused CSS estimated via coverage analysis.
- [ ] **Font Loading Strategy:** `font-display: swap` (or documented alternative) on all custom fonts; critical fonts identified.

### From DESIGN.md Section 14 — Risk Assessment (auto-populated)
- [ ] **HIGH Risks Resolved:** Every HIGH risk item from Section 14 has a corresponding PRD requirement with acceptance criteria.
- [ ] **MEDIUM Risks Warned:** MEDIUM risk items are listed in "Open Questions / Risks" with mitigation plans.
- [ ] **Risk Acceptance:** If any HIGH risk is intentionally accepted, document rationale and escalate to user.

| Unthrottled scroll handlers: 2 | ` [ ] Throttle scroll/resize with requestAnimationFrame` |
| Layout-property animation: `top` transition found | ` [ ] Animate only transform and opacity for GPU compositing` |
| Hardcoded colors: 14 instances outside tokens.css | ` [ ] Zero hardcoded colors — use design tokens exclusively` |
| CSS Layers present, 3 unlayered styles found | ` [ ] CSS Layers enforced — ALL styles reside in layers` |

### Section 11 — Accessibility → Hardening Checklist

| DESIGN.md Finding | Auto-Populated Checklist Item |
|-------------------|------------------------------|
| `:focus-visible` rules: absent | ` [ ] Implement :focus-visible with --focus-ring token on all interactive elements` |
| `prefers-reduced-motion`: ignored | ` [ ] Respect prefers-reduced-motion — disable non-essential animations` |
| WCAG AA estimate: fail | ` [ ] WCAG AA contrast — all body text meets 4.5:1 minimum` |
| ARIA labels: 0 on 12 interactive elements | ` [ ] ARIA labels — all interactive elements without visible text have aria-label` |
| Heading hierarchy: skipped `h1` → `h3` | ` [ ] Heading hierarchy — single h1 per page, no skipped levels` |

### Section 12 — Browser Support → Hardening Checklist

| DESIGN.md Finding | Auto-Populated Checklist Item |
|-------------------|------------------------------|
| CSS Color Module L5 used, no `@supports` fallback | ` [ ] Firefox @supports not fallback required for both themes` |
| `dvh` units used, no fallback | ` [ ] Modern CSS fallbacks — dvh needs vh fallback for older Safari` |
| `:has()` used for layout | ` [ ] Modern CSS fallbacks — :has() needs JS polyfill or graceful degradation` |

### Section 13 — Performance Budget → Hardening Checklist

| DESIGN.md Finding | Auto-Populated Checklist Item |
|-------------------|------------------------------|
| Animation count: 5 simultaneous | ` [ ] Animation budget — cap simultaneous animations to ≤ 3` |
| Scroll-linked animations: 2 | ` [ ] Animation budget — review scroll-linked animations for performance risk` |
| `font-display`: none set (block default) | ` [ ] Font loading strategy — font-display: swap on all custom fonts` |

### Section 14 — Risk Assessment → Hardening Checklist

| DESIGN.md Risk Level | Item | PRD Treatment |
|----------------------|------|---------------|
| **HIGH** | CSS Color Module L5 — Firefox fallback missing | Becomes **PRD requirement** with acceptance criteria: "Firefox renders correct colors in both themes without `rgb(from)`" |
| **HIGH** | Complex animations — unthrottled | Becomes **PRD requirement**: "All scroll/resize handlers throttled; layout animations removed" |
| **HIGH** | Accessibility — missing focus indicators | Becomes **PRD requirement**: "Every interactive element has visible :focus-visible ring" |
| **MEDIUM** | CSS Layers — new architecture | Listed in **Open Questions / Risks** with mitigation: "Team training on @layer cascade; add architecture checkpoint at 30%" |
| **MEDIUM** | Token compliance — hardcoded values scattered | Listed in **Open Questions / Risks**: "Audit remaining hardcoded values in wave 2; add lint rule" |
| **LOW** | Typography — standard web fonts | Noted for awareness only; no checklist item required |

## Decision Log Format

For each major architectural decision in the PRD, include:
1. **What:** The choice made
2. **Why:** Reasoning with context
3. **Alternative considered:** What was rejected and why
4. **Conditions:** When this recommendation is right, and when it stops being right
5. **Escape plan:** If this goes badly, how do we migrate or reverse?
6. **Validation signals:** Concrete signals that will tell us the choice was right (or wrong)
7. **Challenged instinct:** If the team already leans one way, actively look for reasons they might be wrong
